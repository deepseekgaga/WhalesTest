# Chrome 批量下载、TXT 提取与 Excel 汇总设计

## 1. 目标

构建一个 Chrome Manifest V3 扩展及其 Windows 本地助手。用户点击扩展按钮后，系统从固定 Excel 文件的“CC地址”列读取网址，按表中顺序逐个在 Chrome 专用标签页中访问并下载 ZIP。每个 ZIP 包含一个 JSON 和一个 TXT；系统只保留 TXT，并把 TXT 中四个可配置行名对应的内容写入同一个历史汇总 Excel。

系统面向完全授权、隔离的自建测试环境。设计重点是顺序可追踪、失败可恢复、文件处理可审计，以及避免 Chrome 扩展直接访问任意本地文件的权限限制。

## 2. 已确认的固定路径

- 输入 Excel：`C:\Users\HE\Downloads\jingshajingsha\cc来源.xlsx`
- 输入网址列名：`CC地址`
- ZIP 临时下载及最终 TXT 保存目录：`C:\Users\HE\Downloads\jingshajingsha\txt保存`
- 汇总 Excel：`C:\Users\HE\Downloads\jingshajingsha\cc汇总.xlsx`

路径保存在本地助手的固定配置文件中，不在扩展界面提供运行时路径选择。

## 3. 范围

### 3.1 包含

- 点击扩展按钮执行整批任务。
- 读取 `.xlsx` 中“CC地址”列的 HTTP/HTTPS 网址。
- 严格按 Excel 行顺序逐个访问和下载。
- 只处理 `.zip`。
- 验证 ZIP 中恰好存在一个 TXT；JSON 和其他内容不进入结果目录。
- 将 TXT 按 ZIP 基础文件名保存为 `<ZIP基础文件名>.txt`，以便追踪并避免内部 TXT 同名覆盖。
- 从 TXT 中按四个可配置行名提取内容。
- 创建或追加历史汇总 Excel。
- 为每条输入链接写入一条“成功”或“失败”记录。
- 显示进度并写入不含 TXT 内容的运行日志。
- 支持中断后的安全恢复。

### 3.2 不包含

- 登录、验证码或 MFA 绕过。
- 页面表单操作、爬取或站点发现。
- RAR、7z 等非 ZIP 格式。
- 云端服务、数据库或远程日志。
- 在扩展界面编辑输入、输出路径。

## 4. 方案选择

采用“Chrome MV3 扩展 + Python Native Messaging 本地助手”。

- 扩展负责用户启动、专用标签页导航、下载状态监听、进度展示和任务协调。
- 本地助手负责 Excel 读写、ZIP 校验和解压、TXT 筛选、编号分配、清理、日志和恢复状态。
- Native Messaging 只允许指定扩展连接，不开放本地 HTTP 端口。

未采用本地 Flask 服务，因为它需要常驻监听端口和额外的本地接口保护。未采用纯 Python 浏览器自动化，因为用户要求从 Chrome 扩展按钮启动并在 Chrome 内执行。

## 5. 组件设计

### 5.1 Chrome 扩展

- `manifest.json`：Manifest V3 配置，声明 `nativeMessaging`、`tabs`、`downloads`、`storage` 等最小权限。
- 后台 Service Worker：维护任务状态，通过长连接 Native Messaging 与本地助手通信，驱动专用标签页，关联当前网址与下载项。
- 弹出页：提供“开始整批任务”按钮，显示当前序号、总数、成功数、失败数、当前网址和最近错误。
- 扩展徽标：弹出页关闭后仍显示执行进度或失败状态。

扩展不读取 TXT 内容，也不直接读写 Excel。运行中的 Native Messaging 长连接用于维持任务通信；同时任务状态会同步到 `chrome.storage.local`，以便界面重开后恢复显示。

### 5.2 Windows 本地助手

- 通过 Native Messaging 的长度前缀 JSON 协议收发消息。
- 使用 Python 标准库处理 ZIP、路径、原子文件替换和日志。
- 使用 `openpyxl` 读写 `.xlsx`；这是唯一计划引入的第三方运行依赖。
- PowerShell 安装脚本创建隔离 Python 环境、安装锁定版本依赖、生成 Native Host manifest，并写入当前用户的 Chrome Native Messaging Host 注册表项。
- Native Host manifest 的 `allowed_origins` 只包含本扩展 ID。

### 5.3 固定配置

配置包含：

```json
{
  "input_excel": "C:\\Users\\HE\\Downloads\\jingshajingsha\\cc来源.xlsx",
  "url_column": "CC地址",
  "txt_directory": "C:\\Users\\HE\\Downloads\\jingshajingsha\\txt保存",
  "output_excel": "C:\\Users\\HE\\Downloads\\jingshajingsha\\cc汇总.xlsx",
  "download_timeout_seconds": 180,
  "field_mappings": {
    "A": "",
    "B": "",
    "C": "",
    "D": ""
  }
}
```

A、B、C、D 的行名先留空，开发完成后由用户填写配置，无需修改代码。空映射不参与字段缺失判定，对应单元格留空。

## 6. 数据流

1. 用户点击扩展按钮。
2. 扩展连接本地助手并发送预检请求。
3. 本地助手验证输入表、列名、TXT 目录和汇总表可写性。若汇总表被 Excel 占用，整批任务在下载前停止。
4. 本地助手读取“CC地址”列，过滤空单元格，拒绝非 HTTP/HTTPS 值，并返回保留原始行顺序的任务清单。
5. 扩展为任务创建或复用一个专用标签页，逐条导航到当前网址。
6. 扩展监听新下载项，并使用当前网址、开始时间和下载 URL 关联下载；同一时刻只允许一个任务下载。
7. 如果标签页导航未在短等待窗口内创建下载，扩展使用 `chrome.downloads.download` 对同一 URL 做一次受控回退。
8. 下载完成后，扩展把下载项的实际绝对路径及当前任务信息发送给本地助手。
9. 本地助手立即处理该 ZIP、保存 TXT、提取字段并原子追加汇总记录，然后返回成功或失败结果。
10. 扩展更新界面和徽标，再执行下一条。
11. 所有条目结束后，扩展显示整批统计，本地助手关闭本次运行状态。

逐条“下载—处理—落表”可确保中途退出时已完成的数据已经持久化，而不需要在全部下载完成后再统一处理。

## 7. ZIP 与 TXT 处理

### 7.1 ZIP 校验

- 下载文件必须可由 ZIP 读取器打开。
- ZIP 内必须恰好有一个常规 TXT 文件。
- JSON 不解压到最终目录。
- 防止 ZIP Slip：拒绝绝对路径、盘符路径和包含 `..` 越界段的成员名。
- 不信任 ZIP 内部目录；最终 TXT 统一写为 `<ZIP基础文件名>.txt`。

### 7.2 TXT 解码

按以下顺序尝试解码：

1. UTF-8 with BOM
2. UTF-8
3. GB18030

全部失败则该条目标记为失败。日志只记录编码失败，不写入 TXT 原文。

### 7.3 行名提取

四个配置项分别映射到输出列 A、B、C、D。解析器支持：

- `行名: 内容`
- `行名：内容`
- `行名=内容`
- `行名<Tab>内容`

匹配前会去除行名两端空白并执行不区分英文大小写的精确匹配。只提取第一个匹配行的分隔符后内容并去除两端空白，不使用模糊子串匹配，以避免相似行名产生错误数据。

当某个非空配置行名未找到时，该单元格留空，该链接记录为“失败”，日志列出缺失的输出列名。空配置行名是正式支持的占位状态，不会单独导致任务失败。

## 8. 汇总 Excel 规则

工作表名固定为“汇总”，固定表头为：

| 编号_文件名 | A | B | C | D | 是否执行成功 |
| --- | --- | --- | --- | --- | --- |

每条输入链接对应一行，并按输入 Excel 的顺序写入。

### 8.1 编号

- 从首列所有符合 `^(\d+)_` 的历史记录中取最大编号。
- 新任务从最大编号加一开始，每条链接均消耗一个编号，包括失败链接。
- 1 至 9999 使用至少四位补零格式，如 `0001`。
- 超过 9999 后自然扩展为五位或更多位，不截断。

### 8.2 首列

- 已取得 ZIP 文件名时：`0001_原ZIP文件名`，去掉末尾 `.zip`，保留其余名称。
- 下载阶段未取得 ZIP 文件名时：`0001_下载失败`。
- 下载成功但后续解压或解析失败时，仍使用已知的原 ZIP 文件名。

### 8.3 成功状态

- “成功”：ZIP 下载完成、ZIP/TXT 校验通过、所有已配置字段均成功提取、TXT 成功保存且汇总行成功写入。
- “失败”：下载、ZIP 校验、TXT 解码、已配置字段提取或文件保存任一环节失败。
- 失败行的 A–D 中已安全取得的值可以保留，未取得的值留空。
- 如果汇总表本身在运行中变得不可写，系统无法可靠写入对应失败行，因此停止后续任务并在外部日志及扩展界面报告批次级致命错误。

每次追加通过同目录临时文件保存成功后再替换原文件。首次运行时自动创建工作簿和表头；历史表头不符合约定时预检失败，不自动覆盖。

## 9. 清理与文件保留

- 成功处理后删除原 ZIP 和临时解压目录，只在 `txt保存` 中保留重命名后的 TXT。
- JSON 永不写入最终目录。
- 失败时清理 ZIP 和临时目录；如果 TXT 已经安全提取，则允许保留该 TXT 供核查，目录中仍只有 TXT。
- 清理失败写入日志，但不得覆盖主要处理错误。

## 10. 恢复与幂等性

- 本地助手保存当前批次状态：输入行、网址、分配编号、已知 ZIP 名称、处理阶段和最终结果。
- 扩展保存当前进度摘要，供弹出页和徽标恢复显示。
- 重启任务时，已在汇总表中成功落表的当前批次条目不重复追加。
- 历史 ZIP 名称也用于跳过已处理文件。用户已确认正常数据不会出现同名 ZIP。
- 失败记录保留在历史汇总表中；再次执行同一输入将作为新一次执行获得新编号，不覆盖旧记录。

## 11. 错误处理

- 单条可恢复错误：网址无效、下载失败或超时、非 ZIP、损坏 ZIP、TXT 数量异常、TXT 解码失败、字段缺失、TXT 保存失败。写入失败行后继续下一条。
- 批次级致命错误：输入表不存在、缺少“CC地址”列、输出表头不兼容、输出表预检不可写、Native Messaging 连接丢失且无法恢复、运行中输出表不可写。停止批次并保留已完成结果。
- 默认下载超时 180 秒，可通过固定配置调整。
- 日志记录时间、批次 ID、输入行号、网址、ZIP 文件名、分配编号、阶段、结果和错误码，不记录 TXT 字段内容。

## 12. 安全约束

- 只接受输入 Excel 中的 HTTP/HTTPS URL。
- Native Messaging 仅允许指定扩展 ID。
- 不开放本地监听端口。
- ZIP 解压实施路径穿越防护。
- 不执行 ZIP、JSON 或 TXT 中的任何内容。
- 扩展不申请页面内容读取权限，不注入 Content Script。
- 日志不记录 TXT 内容，降低研究数据意外扩散风险。

## 13. 测试设计

### 13.1 本地助手单元测试

- 输入 Excel 读取、空行过滤和列缺失。
- 四种分隔符、大小写和空白归一化。
- 空映射、已配置字段缺失和部分成功值保留。
- UTF-8 BOM、UTF-8、GB18030 及不可解码内容。
- 历史最大编号、四位补零和超过 9999。
- 首列成功名、已知文件名失败、未知文件名失败。
- ZIP Slip、损坏 ZIP、零个 TXT、多个 TXT、JSON 忽略。
- TXT 重命名、ZIP/临时目录清理。
- 工作簿创建、原子追加、历史表头验证和成功/失败状态。

### 13.2 扩展单元测试

- 按顺序驱动任务。
- 下载创建、完成、失败和超时状态机。
- 导航未触发下载时的单次 API 回退。
- 非任务下载不被错误关联。
- 弹出页关闭后进度仍由后台维护。
- Native Messaging 错误及批次终止。

### 13.3 集成测试

- 本地 HTTP 测试站提供多个不同文件名的 ZIP。
- 测试成功、404、超时、损坏 ZIP、字段缺失等混合批次。
- 验证输入顺序、全局编号、每链接一行、成功/失败列和最终目录仅含 TXT。
- 中途终止并重启，验证已落表记录不重复。

### 13.4 最终验收

用户提供真实样例链接后，在 Chrome 中加载未打包扩展，执行一次完整批次并核对：

- 地址按 Excel 顺序访问；
- ZIP 正确下载和清理；
- TXT 正确保留；
- A–D 按用户后续填写的行名提取；
- 汇总编号延续历史；
- “是否执行成功”与实际结果一致。
